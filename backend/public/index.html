An agent that can prove what it did.

Somnus reads live order books, forms its own probability estimates, and trades inside hard limits you set. Every decision, order and rule change is written to a signed hash chain — so you never have to take its word for anything, including the losses.

What it does

Three things, and it will show you the evidence for all of them.

Prices its own opinion

Driftless GBM with horizon-matched volatility, not naive sqrt-scaling. It compares that to the book and acts only where there is genuine edge — which most cycles means not at all.

See its record

Trusts only what it measured

Each window length is scored against its own base rate. One-minute windows are blocked outright — 3,110 samples said they were no better than a coin flip.

Open the tier table

Refuses on its own terms

Daily loss, drawdown, loss streak, execution failures, stale data, clock drift, a dead book feed. Enforced server-side, and the reason is always recorded.

Roughly 95% of that loss is four trades. On 30 August, inside ninety seconds, Somnus placed four orders of about 1,000 tUSDC each against a 1,000 ceiling. They cost 3,999 and returned 990. The other 72 fills risked 449 between them and came out close to flat.

Two bugs, both caught by this repository's own instrumentation and both fixed. Exposure was compared against a counter held in memory rather than positions actually on-chain, so four orders fitted inside a ceiling meant for one. And cost basis was recorded against the requested size: the first of those trades asked for 1,976 contracts, filled 990, and was booked at 999.86 — a position that cost about 501, paid out 990, and won, written into the ledger as a loss.

The per-trade cap is 2 tUSDC now and exposure is read from the chain. The reason those two bugs can be described this precisely is the record the loss is stored in — so the number stays. One that looked better and could not be interrogated would be worth less.

Do not trust the numbers above. Check them.

Every entry carries the hash of the one before it, so nothing can be reordered or removed without breaking the chain, and most are signed with the wallet that placed the trades. The button below runs the real check against this server — no key required, because an audit that needs the operator's secret is not an audit.

POST /api/proof/verify 
Not run yet. Nothing is cached client-side — this calls the server when you press it.

Signature recovery costs about 36 ms an entry, so one request checks linkage over everything and signatures over the most recent 400, reporting exactly what it skipped. That limit exists because leaving it off made a single anonymous request cost 78 seconds of CPU — found while auditing this project, and fixed rather than hidden.

Set up · about 30 seconds

There is no dashboard. Your coding agent is the interface.

Somnus speaks MCP, so you point whatever you already code in at one URL and then ask it questions in English — is it trading right now, and what's blocking it? Twelve read-only tools need no credential at all.

Add an x-somnus-token header and seven more appear, backed by a wallet derived from that token — HMAC(server secret, your token), so the same token always returns the same wallet and none of it is stored. Use a long random string and keep it like a password, because it is the only thing that controls the wallet. Testnet only.

Not listed, or your build only speaks stdio? Every client below is really just pointing at https://somnus-backend.onrender.com/mcp. For one that cannot do HTTP directly, bridge it: npx -y mcp-remote https://somnus-backend.onrender.com/mcp.
